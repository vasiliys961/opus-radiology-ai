# Opus Radiology AI

Самостоятельный исследовательский прототип браузерной станции КТ/МРТ, использующий идеи и наработки [Doctor Opus](https://github.com/vasiliys961/doctor-opus).

> **Не медицинское изделие. Не для принятия клинических решений.** Используйте только синтетические или должным образом обезличенные исследования. Диагностическая точность не валидирована.

## Текущий статус: v0.3 — проверка DICOM-серий и отображения

- Просмотр JPG/PNG/WEBP локально, без отправки на сервер.
- **Предпросмотр DICOM:** несжатые монохромные одиночные кадры (Part 10, Explicit/Implicit VR Little Endian, 8/16 бит), Window Center/Width, Rescale Slope/Intercept, MONOCHROME1/2.
- Загрузка множества файлов **или папки DICOM** через браузер (если выбор папок поддерживается браузером).
- Индексация заголовков в пределах 512 КБ на файл, группировка по `StudyInstanceUID`, `SeriesInstanceUID`, `FrameOfReferenceUID`.
- Сортировка срезов по физической координате вдоль нормали плоскости **только когда ориентация, геометрия и положения совместимы**. Иначе отображается предупреждение, порядок — по Instance Number/имени, 3D не разрешается.
- Переключение срезов в серии: стрелки, слайдер и клавиатура (в фокусе области просмотра).
- Клинический контекст пока хранится только в памяти страницы.
- **20 автоматических тестов** DICOM-декодера и индексации серий.
- Раздельная проверка сортировки срезов и пригодности геометрии для будущей объёмной реконструкции: равномерность шага, Pixel Spacing, SOP UID, ориентация, наклон/смещение и мультифреймовые объекты. Флаг пригодности — только предварительная проверка; 3D по-прежнему не реализовано.
- Исправлены `High Bit`, пороговое окно `WW=1`; неподдерживаемые палитровые DICOM отклоняются, а предпросмотр файла ограничен 64 МБ, чтобы не перегружать Mac M1.

### Пока не реализовано

- Декодирование сжатых DICOM (JPEG2000/JPEG-LS/RLE), мультифреймового DICOM, DICOM без Part 10; полноценный Cornerstone3D.
- Восстановление объёмов, MPR/3D, DICOM SEG, регистрация, количественные измерения и модели сегментации.
- Нативное чтение NIfTI/ZIP: файлы можно добавить, но пока нельзя отобразить.
- Работа TotalSegmentator/MONAI, Gemini/Claude/GPT, сохранение данных и формирование заключений.

**Важно:** поддержка индексации сжатого DICOM по техническим тегам не означает поддержку декодирования его пикселей. Неподдерживаемые файлы отклоняются; ошибок не интерпретируем как отсутствие патологии.

## Запуск на Mac M1

Node.js 22+. В репозитории `web/` используется Next.js 16.4.0.

```bash
cd web
npm install
npm run dev
```

Откройте адрес, показанный в терминале (`http://localhost:3000` или следующий свободный порт). Тестирование: `npm test`. Проверка типов и production-сборки: `npm run typecheck` и `npm run build`.

Если приложение уже клонировано в `~/Desktop/opus-radiology-ai-github`, его можно обновлять:

```bash
cd ~/Desktop/opus-radiology-ai-github
git pull --ff-only
cd web
npm run dev
```

Остановите предыдущий `npm run dev` через Ctrl+C перед обновлением. **Не удаляйте** старую папку `~/Desktop/Opus Radiology AI`: это другой прототип.

## Архитектура

- `web/`: Next.js + локальный браузерный просмотр; все изображения остаются на устройстве пользователя.
- `services/imaging-ai/` (план): независимый CPU/GPU Python inference-процесс без PyTorch в Next.js.
- `services/llm/` (план): защищённый шлюз к агрегаторам LLM с ключами только на серверной стороне.
- `storage/` (план): приватное хранилище исследований вне публичных репозиториев.

Далее — интеграция Cornerstone3D и проверяемая геометрия DICOM, потом MPR/3D, специализированные открытые модели и связка с клиническим контекстом. См. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и [аудит Doctor Opus](docs/DOCTOR_OPUS_AUDIT.md).

**Лицензии:** ни закрытые веса, ни чужой код без лицензионного аудита в публичный репозиторий не копируются. Медицинские файлы и API-ключи туда также не попадают.
