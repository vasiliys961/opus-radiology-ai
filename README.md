# Opus Radiology AI

## Единая рабочая станция (v0.9 · интерактивный MPR)

Стартовый экран `/` объединяет первоначальный трёхколоночный интерфейс и
экспериментальный Cornerstone3D. При выборе DICOM-серии кадры отображаются
**в центральной области**, без перехода на вторую страницу и повторной загрузки.
Левая панель показывает DICOM-серии и проверку геометрии, правая — локальный
клинический контекст и будущие AI-модули. Листание срезов внутри Cornerstone
синхронизировано с выбором файла. JPG/PNG/WEBP сохраняют прежний предпросмотр.

Маршрут `/viewer` оставлен только для технической отладки декодера, а не как
отдельная рабочая станция. **Ограниченный исследовательский MPR** (аксиальная, корональная и сагиттальная плоскости) доступен только при подтверждённой геометрии и ограничении памяти. Пользователь подтвердил отображение трёх плоскостей в Safari; геометрическая точность и корректность навигации ещё не валидированы. MPR нельзя использовать для диагностики. **Объёмный 3D рендеринг, AI и клиническая диагностика не реализованы.**
Публичный GitHub не должен содержать реальные DICOM-исследования, ключи или
идентифицирующие сведения; прототип обрабатывает файлы локально в браузере.

Ограничения DICOM-загрузки для 8 ГБ Mac: до 300 файлов, до 1 ГБ суммарно,
до 128 МБ на файл. Даже эти размеры не гарантируют безопасного потребления RAM.


Самостоятельный исследовательский прототип браузерной станции КТ/МРТ, использующий идеи и наработки [Doctor Opus](https://github.com/vasiliys961/doctor-opus).

> **Не медицинское изделие. Не для принятия клинических решений.** Используйте только синтетические или должным образом обезличенные исследования. Диагностическая точность не валидирована.

## Текущий статус: v0.9 — Cornerstone3D + интерактивный MPR

- Просмотр JPG/PNG/WEBP локально, без отправки на сервер.
- **Предпросмотр DICOM:** несжатые монохромные одиночные кадры (Part 10, Explicit/Implicit VR Little Endian, 8/16 бит), Window Center/Width, Rescale Slope/Intercept, MONOCHROME1/2.
- Загрузка множества файлов **или папки DICOM** через браузер (если выбор папок поддерживается браузером).
- Индексация заголовков в пределах 512 КБ на файл, группировка по `StudyInstanceUID`, `SeriesInstanceUID`, `FrameOfReferenceUID`.
- Сортировка срезов по физической координате вдоль нормали плоскости **только когда ориентация, геометрия и положения совместимы**. Иначе отображается предупреждение, порядок — по Instance Number/имени, 3D не разрешается.
- Переключение срезов в серии: стрелки, слайдер и клавиатура (в фокусе области просмотра).
- Клинический контекст пока хранится только в памяти страницы.
- **26 автоматических тестов** DICOM-декодера и индексации серий.
- Раздельная проверка сортировки срезов и пригодности геометрии для будущей объёмной реконструкции: равномерность шага, Pixel Spacing, SOP UID, ориентация, наклон/смещение и мультифреймовые объекты. Флаг пригодности — только предварительная проверка; 3D по-прежнему не реализовано.
- Исправлены `High Bit`, пороговое окно `WW=1`; неподдерживаемые палитровые DICOM отклоняются, а предпросмотр файла ограничен 64 МБ, чтобы не перегружать Mac M1.

### Новый отдельный просмотр `/viewer` (экспериментальный)

- Современный Cornerstone3D 4.18.3: локальная загрузка DICOM-серий, 2D StackViewport, выбор серии, слайдер и стрелки навигации.
- Поддержка сжатых изображений зависит от декодера, браузера и формата; **не подтверждена тестированием на Mac**. Не следует интерпретировать пустой или ошибочный экран как отрицательное исследование.
- Лимиты лабораторного просмотра: до 300 файлов, по 128 МБ каждый и до 1 ГБ суммарно (для M1 8 GB). Эти пределы не гарантируют низкое использование оперативной памяти.
- Предыдущая главная страница `/` остаётся работающим резервным предпросмотром; Cornerstone не загружается до открытия `/viewer`.
- **26 автоматических тестов**: 20 DICOM + 6 проверок ограничений. Полная интеграционная сборка и проверка декодера на Mac требуются отдельно.
- Подробности: [docs/CORNERSTONE_LAB.md](docs/CORNERSTONE_LAB.md).

### Пока не реализовано

- Проверенная поддержка всех сжатых DICOM (JPEG2000/JPEG-LS/RLE), Enhanced multi-frame, DICOM без Part 10; в `/viewer` декодирование экспериментальное, требует тестов на Mac.
- Клинически валидированные MPR/3D, объёмный рендеринг, DICOM SEG, регистрация, количественные измерения и сегментация.
- Нативное чтение NIfTI/ZIP: файлы можно добавить, но пока нельзя отобразить.
- Работа TotalSegmentator/MONAI, Gemini/Claude/GPT, сохранение данных и формирование заключений.

**Важно:** поддержка индексации сжатого DICOM по техническим тегам не означает поддержку декодирования его пикселей. Неподдерживаемые файлы отклоняются; ошибок не интерпретируем как отсутствие патологии.

## Запуск на Mac M1

Node.js 22+. В репозитории `web/` используется Next.js 16.4.0.

```bash
cd web
npm install
npm test
npm run typecheck
npm run dev
```

Откройте адрес, показанный в терминале (`http://localhost:3000` или следующий свободный порт). Тестирование: `npm test`. Проверка типов и production-сборки: `npm run typecheck` и `npm run build`.

Если приложение уже клонировано в `~/Desktop/opus-radiology-ai-github`, его можно обновлять:

```bash
cd ~/Desktop/opus-radiology-ai-github
git pull --ff-only
cd web
npm run dev
```

Остановите предыдущий `npm run dev` через Ctrl+C перед обновлением. **Не удаляйте** старую папку `~/Desktop/Opus Radiology AI`: это другой прототип.

## Архитектура

- `web/`: Next.js + локальный браузерный просмотр; все изображения остаются на устройстве пользователя.
- `services/imaging-ai/` (план): независимый CPU/GPU Python inference-процесс без PyTorch в Next.js.
- `services/llm/` (план): защищённый шлюз к агрегаторам LLM с ключами только на серверной стороне.
- `storage/` (план): приватное хранилище исследований вне публичных репозиториев.

Далее — проверить колесо мыши, перекрестия и синхронизацию плоскостей в Safari, затем перейти к объёмному 3D, специализированным открытым моделям и связке с клиническим контекстом. См. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и [аудит Doctor Opus](docs/DOCTOR_OPUS_AUDIT.md).

**Лицензии:** ни закрытые веса, ни чужой код без лицензионного аудита в публичный репозиторий не копируются. Медицинские файлы и API-ключи туда также не попадают.

## Обработка сложных серий (v0.7)

Если учебный индексатор не может пройти через последовательности DICOM неизвестной длины
или встретил DICOM без преамбулы Part 10, подключается резервный индексатор
на базе `dicom-parser`. Чтение метаданных ограничено 8 МБ на файл, идёт последовательно
и не передаёт изображения в сеть. Интерфейс сообщает наиболее частую причину отказа.
Индексированные файлы могут всё ещё потребовать отдельной поддержки декодирования
в Cornerstone3D. При любых ошибках изображения не следует использовать для диагностики.

## MPR: видимая детализация и интерполяция (v1.0)

MPR показывает фактические Pixel Spacing и межсрезовое расстояние (мм),
сообщает об анизотропии и старается показывать плоскость исходной серии крупнее.
Переключатель `Плавная / Без сглаживания` меняет только рендеринг: линейная
интерполяция даёт плавную картинку, nearest-neighbor показывает исходную
дискретность. **Ни один режим не восстанавливает отсутствующие анатомические
данные и не повышает клиническую точность.**



## v1.1 — opt-in 3D MIP and compact MPR controls

- A fourth **3D MIP** viewport can be enabled inside the working MPR panel, using the same cached voxel volume without a second image decode. It is an intensity projection, **not** a surface mesh, AI segmentation or an anatomically validated 3D reconstruction.
- Mouse-drag and rotation buttons adjust the 3D camera; hiding the panel disables its GPU viewport. MPR plane synchronization remains independent.
- Fixed legacy CSS selector that expanded slice-control rows to 225–310 px and produced large blank blocks under MPR slices.
- Thick-slice series display a high-visibility warning before 3D. On 8 GB Mac M1, the MPR resource gate still applies, and opening the 3D viewport adds GPU pressure.
- A browser-only Safari/WebGL test is still required; automated build cannot validate interactive 3D pixel correctness.
