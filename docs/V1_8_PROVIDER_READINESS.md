# v1.8 — Проверка шлюзов OpenRouter / Polza без данных пациентов

**Ветка:** feature/v1.8-provider-readiness.

## Что работает

На странице Opus Radiology AI → **AI-оркестр → Проверка подключения AI-шлюза**
врач выбирает провайдера и нажимает **«Проверить OpenRouter»** или
**«Проверить Polza»**.

В браузер возвращаются только:

- наличие настроенного серверного API-ключа (булев статус, ключ **не возвращается**);
- серверные идентификаторы Vision и clinical-модели, если указаны;
- для OpenRouter — ответ публично документированного каталога моделей:
  существует ли каждый ID и заявлена ли поддержка **входного изображения,
  текстового вывода** для Vision или **текстового ввода и вывода** для синтеза;
- до 14 примеров заявленных моделей каждого типа;
- ограничения и предупреждения.

**OpenRouter:** официальная документация о GET /api/v1/models:
https://openrouter.ai/docs/api/api-reference/models/get-models

Запрос отправляет серверный API-ключ OpenRouter **самому OpenRouter**
в заголовке Authorization для аутентификации. Никакие DICOM,
клинический текст, документы, имена файлов или данные пациентов не
добавляются в запрос. При отсутствии ключа сеть не используется.

**Polza:** наличие серверного ключа и моделей проверяется локально;
удалённый список **не вызывается**, пока контракт API не подтверждён.
Не делаем вывод о реальной доступности Polza по одному ID.

Каталог моделей не гарантирует, что тариф, география, конечная точка
или конкретный аккаунт позволят выполнить модель. Это **не тест
медицинского AI-инференса** и не клиническая валидация.

## Как проверить на Mac

Проект: ~/Desktop/opus-radiology-ai-github/web.

1. Запустить актуальную ветку в локальном dev-режиме: npm run dev.
2. Открыть http://localhost:3000 (или фактический порт Next.js).
3. AI-оркестр → выбрать OpenRouter → **Проверить OpenRouter**.
4. Если серверный ключ в web/.env.local уже есть, увидите «Настроен».
   Если список моделей недоступен, будет сообщение о сетевой/учётной ошибке.
5. При необходимости добавить **только идентификаторы**, не копируя ключ:

    RADIOLOGY_OPENROUTER_VISION_MODEL=идентификатор_с_реального_каталога
    RADIOLOGY_OPENROUTER_CLINICAL_MODEL=идентификатор_с_реального_каталога

6. Перезапустить npm run dev после редактирования .env.local.

Идентификаторы на странице в выпадающих списках пока хранятся **только
в браузере**. Экспериментальный серверный AI-оркестр берёт их из
переменных RADIOLOGY_*_MODEL, чтобы браузер не мог послать произвольные
модели и произвольные медицинские данные. Никакой реальный клинический
запрос от этой проверки **не становится разрешённым**.

## Security / privacy

- Диагностика доступна только при NODE_ENV=development на localhost /
  127.0.0.1. На production она закрыта HTTP 404.
- Запрещены дополнительные query-поля, POST и cross-site fetch.
- Ответ всегда Cache-Control: no-store; ошибки не содержат upstream body,
  ключей или трассировки. OpenRouter URL фиксированный, нет SSRF.
- Получение каталога ограничено временем 10 секунд и размером 8 MB,
  защищая компьютеры с малым объёмом памяти.
- Неструктурированный POST /api/ai теперь всегда **410 Gone** — даже
  с development bearer token. Аналогичная защита присутствует в PR #6.
- Синтетический /api/ai/orchestrate остаётся отдельным выключенным по
  умолчанию исследовательским endpoint, который генерирует PNG на сервере.
- Ни эта проверка, ни наличие ключа **не разрешают** отправку изображений
  реальных пациентов. Нужны полноценная идентификация врача, согласие,
  проверенное обезличивание metadata + burnt-in pixels, контракт обработки,
  аудит и соответствие юрисдикции и лицензиям.

## Проверки

1. Unit: web/lib/provider-readiness.test.ts — парсинг признаков модальности,
   несовместимые ID, непроверенная Polza, отсутствие ключа, ошибки сети,
   секреты не утекают, потоковый лимит ответа.
2. Browser production: Next server refuses the route (404) and arbitrary
   upload gateway (410), with transparent fallback in the UI.
3. Real localhost development smoke check: scripts/check-provider-readiness-dev.mjs
   runs Next dev with fake credentials, exercises Polza without external traffic,
   validates OpenRouter missing-key status and rejects extra parameters and POST.
4. Standard npm test, npm run typecheck, npm run build and browser DICOM/MPR/3D tests.

**Важно:** GitHub CI не может прочитать web/.env.local на вашем Mac и не
проверяет реальную доступность OpenRouter для конкретного ключа.
Это должен подтвердить пользователь локальной кнопкой «Проверить».
