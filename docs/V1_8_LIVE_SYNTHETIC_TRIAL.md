# v1.8 — Live OpenRouter Research on Synthetic Images

This is the first **real OpenRouter Vision inference path in the UI**, but it
accepts **ONLY non-patient mathematical images generated by this codebase**.
This is not clinical image analysis or a medical device.

## How to run on your Mac

Your existing local server key in **web/.env.local** is sufficient:

    OPENROUTER_API_KEY=<existing secret; never paste it into issues or chat>

No separate RADIOLOGY_OPENROUTER_VISION_MODEL or CLINICAL_MODEL values are
required for this new demo. The researcher selects models explicitly from
OpenRouter's current model catalogue, which the **server checks again** before
performing the paid request.

1. After the PR is merged into main, inside your Cursor clone:

       cd ~/Desktop/opus-radiology-ai-github
       git pull --ff-only origin main
       cd web
       npm run dev

2. Open the address Next.js displays (e.g. http://localhost:3000).
3. In **AI-оркестр**, choose **OpenRouter**, click **«Проверить OpenRouter»**.
4. The site reports whether the server has a key. The key never appears
   in the browser. In the synthetic test below that, choose:
   - Region: **head / chest / abdomen**.
   - Modality label: **CT / MR** (the images remain mathematical).
   - Vision model: a current catalogue entry explicitly declaring image input.
   - Text model: a current catalogue entry declaring text input/output.
5. Accept the **paid synthetic-only experiment** checkbox.
6. Click **«Запустить реальный OpenRouter-тест»**.
7. Wait for the three Vision roles, critic and textual synth to complete.
   If they produce strictly parseable, source-linked JSON, the UI displays
   the structured observations, uncertainties and unverified draft.
8. Enable sound in the AI panel beforehand if you want **«дзинь» after success**.
   Click «Проверить звук» first in Safari if needed. No ding on failure.
9. Download the nonclinical experiment JSON for review.

**This actually calls provider models** and can incur charges! Each completed
trial requests up to 5 model completions, with max **1200 output tokens per
request**. Image-input charges, provider differences and possible early
failed charges remain. Set an OpenRouter spending limit yourself first.
The local server also has a best-effort **one-at-a-time, four-starts-per-ten-
minutes** guard; it resets on Next.js restart and is not a billing control.

## Security contract

The developer-only /api/ai/synthetic-demo endpoint:

- Is **HTTP 404** on any production deployment; only next dev on
  localhost/127.0.0.1 is usable.
- Requires same-origin JSON POST from the local app; refuses cross-site
  browser requests, unauthorised Host and query parameters.
- Allows only: modality ("CT"/"MR"), region ("head"/"chest"/"abdomen"),
  a Vision catalogue ID, a clinical catalogue ID, and acknowledgement of
  paid synthetic-only research. No extra keys.
- Enforces max request size 700 bytes in streaming mode, even if no
  Content-Length header exists.
- Gets the API key from Node environment only. It never sends the key to the
  browser; the key goes to OpenRouter to authenticate calls.
- Re-queries the actual OpenRouter catalogue and checks the declared model
  input/output modalities server-side. **Catalogue listing is not
  entitlement or clinical validation.**
- Generates two 96×96 grayscale PNG mathematical phantoms on the server.
  No DICOM, uploaded medical images, reports, pixel burns or medical context
  are consumed, and the client cannot substitute data.
- Sends the two images to 3 distinct research Vision roles and a critic.
  A separate reasoning-model call prepares a nonclinical, unverified draft.
- Requires exact reviewed image IDs and source SOPS for evidence; incorrect
  or non-JSON provider output fails the trial without sounding the bell.
- Does **not** make real-patient AI inference available. The unrestricted
  /api/ai route stays retired (410 Gone).

## Tests and limitations

Automated CI unit tests mock both provider catalogue and model responses
and verify strict payloads, source identity, image integrity and budget.
An integration test starts a real Next dev server with **no real API key**
and verifies rejects for PHI-bearing payloads, wrong Origin, missing cost
confirmation and oversized requests, without any external paid inference.

The real OpenRouter credential is stored **only on your Mac**. GitHub CI
has no access to it; therefore actual provider latency, account eligibility,
response formatting and billing can be checked only after the user clicks
Run locally. If a chosen model refuses JSON or returns truncated output,
the experiment reports failure. It does not imply the model is unable
to interpret real clinical DICOM volumes.

Mathematical brain, chest and abdomen shapes test software plumbing,
**not medical performance**. We cannot infer segmentation Dice, pathology
sensitivity/specificity, lesion recall, anatomical accuracy or patient
safety from these tests.

To introduce real cloud-assisted medical analysis later we must finish
physician authentication, consent, explicit study-specific authority,
DICOM tag AND burned-in pixel de-identification, auditable provenance,
provider governance and approved jurisdiction. Tag-stripping alone
does not prove privacy.
