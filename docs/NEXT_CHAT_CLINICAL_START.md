**Решение владельца от 28 октября 2026; приоритетнее старой очереди детекторов.**

## Цель
Довести приложение до цельной функциональной врачебной рабочей станции **v2.0**.
СНАЧАЛА соединить существующие настоящие исполнители/детекторы, DICOM viewer,
Gemini Vision, Claude Opus, Evidence и врачебный review в **один реально
работающий путь**. ПОТОМ углублённо шлифовать, сравнивать, оптимизировать и
независимо валидировать каждый детектор. Не делать витрину с фальшивыми
результатами, макет автоматического запуска или чисто архитектурный PR без
новой доступной врачу функции.

## Точное ТЗ для MVP v2
1. **Вход:** врач выбирает папку DICOM (КТ либо МРТ). Все серии группируются по
   оригинальным UID; подлинные пиксели и геометрия остаются привязанными к
   исходному исследованию. Интуитивно понятная основная кнопка
   **«Анализировать исследование»**, по возможности автоматический запуск;
   технические настройки только в «Дополнительно».
2. **Распознавание:** модальность, анатомия, протокол/фаза/последовательность,
   проверка геометрии и пригодности; при нехватке метаданных — статус
   «не определено», а не выдуманное FLAIR/T1CE/CTPA.
3. **Исполнение:** автоматический выбор действительно установленных
   совместимых настоящих детекторов (локальный браузер, Mac CPU/MPS,
   приватные Linux CPU/GPU). Первая интеграция: КТ узлы лёгких (MONAI),
   КТ головы кровоизлияния (ianpan), МРТ FLAIR WMH (wmh_seg).
   Состояния: готов, выполняется, нет весов, неподходящий протокол,
   заблокирован приватностью/ресурсами, ошибка, результат; отмена/повтор.
   Не выдавать наличие кода за работающий инференс и не дублировать
   исследовательские панели вместо основного пути.
4. **LLM:** на каждом открытом КТ/МРТ планировать анализ **Gemini Vision**
   по разрешённым обезличенным реальным кадрам/сериям в экономном объёме,
   независимо от специализированных моделей; не скрывать неполный охват.
   Затем **Claude Opus** собирает реальные выводы Gemini + детекторов,
   выделяет согласия/расхождения, неопределённости, дифференциальный ряд.
   Провайдеры и расход управляемы. Если приватность/полномочия/бюджет/
   провайдер запрещают вызов — явный статус и независимый локальный путь.
   Не считать одну галочку доказательством обезличивания.
5. **Доказательства:** каждый найденный очаг связан с оригинальным SOP UID,
   срезом и координатами LPS/RAS, размерами/объёмом, моделью/версией,
   SHA-256, оценкой охвата; кликабельная навигация на оригинал/MPR.
   Нельзя создавать «нет патологии» при непроверенной зоне.
6. **Врач:** принять/отклонить/не оценивать находку; редактируемое
   **предварительное** заключение с оговорками; клиническое решение,
   подписание и ответственность — у врача. Сохранять связь с доказательствами.
7. **Режимы:** Browser / Local Mac-PC / private CPU / private GPU.
   На Mac M1 8GB не загружать тяжёлые веса в браузер и ограничивать RAM.
   Файлы пациентов/секреты не помещать в публичный GitHub.
   Реальные исследования в облаке — только с подтверждённым обезличиванием,
   допустимостью передачи, полномочиями врача и контролем стоимости.
8. **Приёмка v2 функциональности:** врач без командной строки открывает
   одну разрешённую публичную КТ и одну МРТ, нажимает одну кнопку,
   видит реальный запуск поддерживаемых детекторов, локализованные
   результаты или честный отказ, Gemini/Opus при допуске,
   может проверить/исправить предварительный отчёт.
   CI на реальных модулях — только технический этап; отдельная независимая
   диагностическая точность и нормативная готовность **НЕ приписываются** v2.

## Как работать
Самостоятельно: проверить свежий main и AGENTS.md → выбрать наиболее полезный
незаконченный сквозной участок → новая ветка → медицинский код и реальный UI
→ тесты → GitHub Actions → squash merge только после GREEN → следующий участок.
Не спрашивать пользователя о рутинных действиях. Отчитываться коротко по
готовому модулю. Основной KPI — какие новые действия доступны врачу, а не PR.
Ни одного фиктивного клинического результата.

# Opus Radiology AI — продолжение клинического маршрута (вставить в новый чат)

## НАША ЦЕЛЬ И МАРШРУТ — НЕ МЕНЯТЬ БЕЗ ЯВНОГО РЕШЕНИЯ

Мы строим **универсальную врачебную платформу для комплексного анализа КТ и МРТ**, а не демонстрацию LLM или набор технических тестов. Главный результат — **реальные специализированные детекторы разнообразных патологий**: грудная клетка, головной мозг, сердце и сосуды, живот, забрюшинное пространство, позвоночник, таз и суставы. Каждый обнаруженный очаг должен иметь исходный срез, координаты, размер/объём, SHA источника, точную версию модели, воспроизводимые доказательства и право врачебного подтверждения.

**Постоянный стратегический маршрут (ПРОЧИТАТЬ ЦЕЛИКОМ):**
- [docs/CLINICAL_DEVELOPMENT_PATH.md](docs/CLINICAL_DEVELOPMENT_PATH.md) — последовательный путь: охват патологий → подлинный инференс → независимая точность → MPR/Evidence → независимые Gemini/Opus и врач → клинический выпуск;
- [docs/CLINICAL_DETECTOR_EXPANSION_DIRECTIVE.md](docs/CLINICAL_DETECTOR_EXPANSION_DIRECTIVE.md) — обязательная широкая карта болезней и критерии;
- [docs/clinical-detector-coverage.json](docs/clinical-detector-coverage.json) — актуализируемый реестр детекторов;
- [AGENTS.md](../AGENTS.md), [REQUIREMENTS.md](../REQUIREMENTS.md), [docs/OPUS_RADIOLOGY_MASTER_SPEC.md](OPUS_RADIOLOGY_MASTER_SPEC.md) — правила и конечный продукт.

**Принцип:** сначала закрывать реальные клинические пробелы, используя уже обученные оригинальные модели и доступные лицензированные публичные исследования, а не бесконечно проверять синтетические примеры. Зелёный CI, проверенный SHA весов, реальный forward, Dice на одном случае и независимая клиническая валидация — пять **разных** ступеней. Не утверждать качество без источника и правильного знаменателя.

**Ближайшая очередь:** QTIM пять моделей метастазов мозга T1CE → CLN опухоли лёгких → Raidionics лимфоузлы средостения → ТЭЛА CTPA (замена слабого) → опухоли почек → WMH FLAIR fold0 → RSNA Knee 12 признаков с сохранёнными весами и сообщённым пользователем 0,956 (не подменять 0,808) → ILD, живот, позвоночник, костные метастазы, коксартроз/остеонекроз, таз. Одна заблокированная модель не останавливает работу над следующими задачами.

**Работа без постоянных вопросов:** текущий `main` → короткая ветка → реальный медицинский код → достаточные проверки → только успешный обязательный CI → самостоятельный squash merge → SHA → следующая клиническая задача. Ошибки реального инференса устранять на ветке; не сливать неудачный эксперимент. Не переписывать работающие DICOM/MPR/3D.

**Ресурсы и безопасность:** Mac M1 8GB не перегружать. Тяжёлые веса/инференс — отдельно на CPU/GPU. Оригинальные снимки пациентов/PHI/секреты не публиковать. Облачный анализ реальных КТ/МРТ разрешается только при подтверждённых правах, полном обезличивании и проверенной политике передачи, не через одну галочку. Gemini и Opus могут анализировать параллельно, но с отслеживаемым входом и сохранением расхождений; решение принимает врач.
