# Сравнение реальной Gemini/Opus-цепочки с doctor-opus-global

Проверено live main материнского репозитория:
`e6cc734d70d553b20bfcf535cf651e77b2386af9` (01.11.2026).
Наш локальный код: `466981a` (после реального NLST-теста и пояснения MPR).
Это сравнение кода и ограничений, не измерение клинической точности.

## Что в действительности делает материнское приложение

Основная ветка нескольких изображений `/api/analyze/image` при streaming
вызывает `analyzeMultipleImagesOpusTwoStageStreaming`, а не общий многоагентный
диагностический консилиум. Не следует смешивать эти независимые маршруты.

- `getDescriptionPrompt` задаёт Gemini роль визуального наблюдателя с критериями
  КТ/МРТ. JSON включает morphology/локализацию, положительные и важные отрицательные
  наблюдения, измерения, качество/артефакты, неопределённости, critical flags,
  routing и provenance. Диагноз/лечение наблюдателю запрещены.
- `prepareVisionDataForTextPrompt` переносит наблюдения с самооценкой ≤0.7 или
  без числовой самооценки в `uncertain_findings`, не удаляя их. Числа самооценки
  не являются доказанной вероятностью диагноза или калиброванной уверенностью.
- На втором этапе **в streaming-ветке нескольких изображений Opus получает
  JSON, клинический контекст И ВСЕ приложенные к этому запросу изображения**.
  Он видит их одновременно с Gemini-описанием, а не в слепом чтении.
  Это не означает просмотра всей исходной DICOM-серии: речь о переданных кадрах.
- `RADIOLOGY_PROTOCOL_PROMPT` требует систематическое описание и Impression.
  Другие режимы/непотоковые функции могут отличаться; вывод выше относится
  к прослеженному реальному маршруту, не ко всем функциям репозитория.

## Что делает наш модуль сейчас

Основа «Gemini → JSON всех полученных наблюдений → Opus» сохранена.
`visualRecheck` — дополнительный список для выбора картинок, не замена JSON.
`makeSafeVolumeOpusInput` передаёт ВСЕ принятые наблюдения, а не только отмеченные
кадры. Однако схема беднее: номер среза, anatomy, sign, uncertainty и limitations.
Промпт ограничивает группу шестью краткими наблюдениями и просит не перечислять
рутинную норму. Явного органного покрытия и отдельных важных отрицательных
наблюдений сейчас нет. Обработка группами также ограничивает межсрезовый контекст.

Слепой визуальный Opus получает только отобранные точные копии, окна и исходные
номера — без диагнозов Gemini. Затем ДРУГОЙ вызов Opus составляет протокол из
всех текстовых наблюдений и слепого чтения, клинического контекста и доступных
детекторных фактов. Финальный синтез сам изображения не получает.

В реальном NLST-тесте Gemini видел десять кадров; визуальный Opus — 61,62,68,69;
финальный Opus — описания десяти и результаты визуального чтения четырёх.
Если Gemini не заметит очаг и не отметит срез, при отсутствии подходящего
детекторного якоря он может не попасть во второе визуальное чтение.

## Что стоит объединить

1. Вернуть богатый **наблюдательный** JSON Gemini: структура/орган,
   локализация в проверенной системе координат, морфология, признаки,
   качество, конкретные ограничения, значимые отрицательные признаки только
   в реально видимой области. Отдельные состояния «видно / частично видно /
   не оценено» не дают превращать пустые поля в норму.
2. Отбор изображений оставить отдельным каналом: что требует перепроверки
   и почему, с исходным номером. Не сокращать ради этого остальные наблюдения.
3. Для небольшого врачебного выбора до 16 кадров рассмотреть отдельный режим
   независимого чтения Opus **всего выбранного набора**; для длинной серии —
   ограниченный целевой просмотр с точным охватом. Это предложение, в текущий
   код оно ещё не внесено. Оно меняет прежнюю экономную политику «нет очага —
   нет дополнительного визуального запроса», его цену следует учитывать явно.
4. Сохранить финальное согласование: какие признаки совпали, какие появились
   только у одного читателя, что не оценено и что требует врача. Подробный
   JSON может потребовать изменения бюджета контекста/выходных токенов;
   нельзя молча отбрасывать наблюдения ради прежних лимитов.

Не переносить механически: обязательные размеры/HU/стадии/классификации без
измерений и нужных серий, «норму по умолчанию», самооценку confidence как
вероятность болезни. Материнские требования чисел и широких МР/КТ-критериев
нужно ограничить реально доступным протоколом и source-bound измерениями.

## Ответ о точности

Подробный наблюдательный JSON и просмотр изображений вторым читателем
снимают конкретные ограничения текущей схемы; слепое чтение сохраняет
независимость от подсказок первого читателя. Это основания для улучшения
архитектуры, не доказательство большей диагностической точности.

Для проверки нужны одинаковые исходные кадры, окна, модели и клинический
контекст, фиксированные версии промптов и экспертный reference. Сравнить:
материнскую цепочку; нынешнюю; объединённую. Отдельно считать пропуски,
необоснованные находки, локализацию, опасные отрицания, соблюдение охвата,
время и расход. Два LongCIU-среза — только пилот; NLST-тест без экспертной
разметки доказывает исполнение, но не правильность находок.

В этом сравнении нет новых платных вызовов, изменений рабочих промптов,
установки моделей или деплоя.
