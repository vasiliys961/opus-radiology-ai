# PATH-ICH-05 · многоклассовая экспертная разметка → бинарный эталон кровоизлияния

Для SAMIHS бинарная маска объединяет внутричерепные кровоизлияния независимо от локализации и подтипа. Многие исследовательские датасеты размечают IPH, IVH, SAH, SDH и EDH **разными числовыми ID**. Сравнение маски SAMIHS только с `--reference-label 1` тогда систематически игнорировало бы часть геморрагических вокселей.

Новый `scripts/build-ich-expert-binary-union.py` выполняет только оператором документированное объединение всех указанных геморрагических ID в **новую** бинарную NIfTI маску со строго прежней геометрией. Исходный экспертный файл не меняется. Ни одна неизвестная ненулевая метка не интерпретируется по догадке: программа отказывает. Она сохраняет SHA исходной КТ, исходной многоклассовой разметки, проверенного описания классов и вычисленной бинарной маски, плюс числа вокселей каждого класса. Без ресемплинга или классификации нейросетью.

### Явный документ источника (пример структуры, НЕ универсальный словарь меток)

```json
{
  "sourceUrl": "https://example.org/exact-dataset-label-ontology",
  "labelMeaning": {
    "1": "IPH",
    "2": "IVH",
    "3": "SAH",
    "4": "SDH",
    "5": "EDH"
  }
}
```

**Цифры выше только иллюстрация формата.** Не применять их к реальному датасету до проверки оригинального словаря классов и прав доступа. Если типы и их числовые ID неизвестны, **отказаться**, а не угадывать.

```bash
python scripts/build-ich-expert-binary-union.py \
  --source-ct /research/authorized-head-ct.nii.gz \
  --expert-labelmap /research/original-multiclass-expert.nii.gz \
  --label-ontology-json /research/dataset-authoritative-labels.json \
  --output-mask /research/derived-expert-ich-binary.nii.gz \
  --manifest /research/derived-expert-ich-binary-manifest.json \
  --source-sha256 <CT_SHA256> \
  --expert-sha256 <ORIGINAL_LABELMAP_SHA256> \
  --ontology-reviewed --rights-attested \
  --public-research-authorization PUBLIC-ICH-LABEL-UNION
```

После вывода бинарной маски подать её в `scripts/run-ich-first-real-case.py` как `--expert-mask`, используя именно её SHA-256 (из нового манифеста). Сохранить оригинальный экспертный файл и манифест преобразования: они нужны для независимого аудита. Текущий объединённый отчёт SAMIHS **не устанавливает тип** кровоизлияния, не является новым экспертным заключением и не доказал клинической точности. Все действия — только на разрешённых исследовательских данных и внешнем Linux CPU/GPU.

**Текущий фактический статус:** программная обработка подготовлена. Конкретные разрешённые исходные КТ/веса SAMIHS/проверенный экспертный mask и метрики реального выполнения до сих пор отсутствуют.

## Отдельное покрытие исходных экспертных классов (PATH-ICH-07)

Если в `run-ich-first-real-case.py` переданы одновременно оригинальная
многоклассовая экспертная NIfTI, авторитетная онтология и паспорт бинарного
объединения, фактический завершённый SAMIHS-инференс теперь дополнительно
получает `ich-original-expert-subtype-coverage.json`. Каждый исходный ID
(например, IPH / IVH / SAH / SDH / EDH) содержит:

- экспертные положительные воксели и физический объём, мл;
- сколько вокселей данного класса перекрыто бинарной маской модели;
- сколько экспертных вокселей класса пропущено моделью;
- долю перекрытия, либо null при отсутствии этого класса в эталоне.

Суммарное перекрытие и пропуски **обязаны совпадать** с независимыми 3D TP/FN.
Оригинальные ID и сама двоичная маска перепроверяются на точное соответствие,
не только на одинаковое число вокселей. Недокументированные положительные
метки, иной NIfTI-grid или расхождение счётчиков блокируют итоговый COMPLETE.

**Важно:** это *покрытие экспертных вокселей каждого класса*, а не распознанный
SAMIHS тип кровоизлияния, не lesion sensitivity и не клиническая
чувствительность. SAMIHS по-прежнему выводит одну бинарную маску. Результат
остаётся исследовательским и не публикуется как диагностическая точность.

Лимит полного объединения по геометрии согласован с ранее допустимым
объёмом SAMIHS (512×512×400); оперативная память внешнего сервера всё равно
должна быть достаточной. Данные пациентов в GitHub Actions не используются.

## Врачебная оценка экспертных подтипов в браузере (PATH-ICH-08)

После проверки исходной КТ, SAMIHS-маски, бинарной экспертной маски и паспорта
3D-сопоставления откройте дополнительную панель «Какие экспертные типы
кровоизлияния покрыты SAMIHS?». Импортируйте локальный
`ich-original-expert-subtype-coverage.json`. Для показа метрик врач должен
отдельно указать **оригинальную многоклассовую NIfTI-маску** и **исходную
онтологию JSON**: их SHA-256 проверяются в браузере на локальных файлах.
Данные не отправляются на сервер. Таблица сортирует IPH/IVH/SAH/SDH/EDH
по числу пропущенных вокселей. Отсутствующие в оригинальном эталоне классы
отмечаются как отсутствие знаменателя, не как 0% чувствительности.

Врач видит исследовательское покрытие экспертных вокселей и объёмы,
а **не автоматическое определение типов SAMIHS**, не диагноз и не
клиническую чувствительность. Ни совпадение SHA, ни JSON не удостоверяют
независимость обучающей и тестовой выборки или право использования датасета.

## Исходный КТ-срез с максимальной ошибкой по экспертному классу

Для каждого документированного IPH/IVH/SAH/SDH/EDH подсчитывается срез
исходной третьей оси NIfTI, содержащий наибольшее число **FN-вокселей данного
экспертного типа**, и их количество. При отсутствии пропущенных вокселей
`peakMissedSliceIndexK` и `peakMissedSliceVoxels` равны null. В
врачебной таблице можно открыть соответствующий k-срез с TP/FP/FN наложением,
после SHA-проверки оригинальной разметки и онтологии. Тип относится только
к экспертной разметке. k не является подтверждённым аксиальным DICOM SOP.
Старые отчёты без двух новых полей по-прежнему доступны без такой навигации.
